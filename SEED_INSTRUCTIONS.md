## ✅ Проверка результатов

### Метод 1: Через Prisma Studio (UI)

```bash
npx prisma studio
```

Переходите в каждую таблицу и проверяйте данные.

### Метод 2: Через SQL запросы

```sql
-- Проверка ролей
SELECT id, name, code, is_system FROM roles ORDER BY name;

-- Проверка разрешений
SELECT id, code, name, module FROM permissions ORDER BY module, code;

-- Проверка связей
SELECT r.name as role, p.code as permission
FROM role_permissions rp
JOIN roles r ON r.id = rp.role_id
JOIN permissions p ON p.id = rp.permission_id
ORDER BY r.name, p.code;

-- Проверка категорий
SELECT id, name, slug, sort_order FROM product_categories ORDER BY sort_order;

-- Статистика по ролям
SELECT r.name, COUNT(rp.id) as permission_count
FROM roles r
LEFT JOIN role_permissions rp ON r.id = rp.role_id
GROUP BY r.id, r.name
ORDER BY r.name;
```

### Метод 3: Через логи

Скрипт выводит подробный лог:

```
✅ = успешно создано
⏭️  = уже существует
❌ = ошибка
```

## 🔐 Структура ролей и разрешений

### Founder (Основатель)

```
Доступ: * (полный)

Разрешения:
  *:* - все операции
```

**Кому:** Администратору, основателю
**Для:** Полное управление всей сетью

### Director (Директор)

```
Доступ: филиал + аналитика

Разрешения:
  - branch.manage (управление филиалом)
  - booking.read (просмотр броней)
  - order.read (просмотр заказов)
  - payment.read (просмотр платежей)
  - station.read (просмотр мест)
  - finance.read (просмотр финансов)
  - analytics.read (просмотр аналитики)
  - user.read (просмотр пользователей)
  - product.read (просмотр товаров)
  - settings.read (просмотр настроек)
```

**Кому:** Директору филиала
**Для:** Управление одним или несколькими филиалами

### Manager (Управляющий)

```
Доступ: операции в филиале

Разрешения:
  - branch.read (просмотр)
  - booking.read/create/edit/cancel (полное управление)
  - order.read/create (просмотр и создание)
  - payment.read (просмотр)
  - station.read/update (просмотр и обновление)
  - finance.read (просмотр)
  - user.read (просмотр)
  - product.read (просмотр)
  - promotion.read (просмотр)
```

**Кому:** Управляющему филиалом
**Для:** Операционное управление филиалом

### Admin (Администратор)

```
Доступ: управление содержимым

Разрешения:
  - booking.read/create (операции с бронями)
  - order.read/create (операции с заказами)
  - payment.read (просмотр платежей)
  - station.read (просмотр мест)
  - user.read/create/edit (полное управление пользователями)
  - product.read/manage (полное управление товарами)
  - settings.read/edit (полное управление настройками)
  - promotion.read/create/edit (полное управление акциями)
```

**Кому:** Администратору контента, редактору
**Для:** Управление содержимым и параметрами системы

### Cashier (Кассир)

```
Доступ: расчеты и платежи

Разрешения:
  - booking.read/create (работа с бронями)
  - order.read/create (работа с заказами)
  - payment.read/create/process (полное управление платежами)
  - station.read (просмотр мест)
```

**Кому:** Кассиру, оператору платежей
**Для:** Обработка платежей и операций

### Staff (Персонал)

```
Доступ: ограниченный операционный

Разрешения:
  - booking.read (просмотр броней)
  - station.read/update (просмотр и обновление мест)
  - order.read (просмотр заказов)
```

**Кому:** Барменам, курьерам, техническому персоналу
**Для:** Операционная работа

### Customer (Клиент)

```
Доступ: только свои данные

Разрешения:
  - booking.read (просмотр своих броней)
  - order.read (просмотр своих заказов)
```

**Кому:** Обычным пользователям
**Для:** Просмотр своих заказов и броней

## 🛠️ Модификация seed

Все конфигурации находятся в `prisma/seed.ts`:

### Добавить новую роль

```typescript
const ROLES = [
  // ...
  {
    name: 'Support Manager',
    code: 'support_manager',
    description: 'Менеджер поддержки',
    isSystem: true,
  },
];
```

### Добавить новое разрешение

```typescript
const PERMISSIONS = [
  // ...
  {
    code: 'support.manage',
    name: 'Управление тикетами поддержки',
    module: 'support',
  },
];
```

### Назначить разрешение роли

```typescript
const ROLE_PERMISSIONS = {
  // ...
  support_manager: ['support.manage', 'ticket.read', 'ticket.respond'],
};
```

После модификации запустите:

```bash
npm run prisma:seed
```

## ⚠️ Важные моменты

1. **Системные роли** - Помечены `isSystem: true` и не должны быть удалены
2. **Разрешение `*:*`** - Специальное, означает полный доступ без ограничений
3. **Зависимости** - Роли создаются ДО разрешений
4. **Уникальность** - Каждая роль и разрешение имеют уникальный код
5. **Целостность** - Используются индексы и уникальные ограничения

## 🐛 Устранение проблем

### Проблема: "no such table"

```
Error: ENOENT: no such file or directory
```

**Решение:**

```bash
npm run prisma:migrate dev
npm run prisma:seed
```

### Проблема: "connection refused"

```
Error: connect ECONNREFUSED 127.0.0.1:5432
```

**Решение:**
1. Убедитесь, что PostgreSQL запущен
2. Проверьте `DATABASE_URL` в `.env`
3. Протестируйте подключение

### Проблема: "TypeScript compilation failed"

```bash
npm install -D ts-node typescript
npm run prisma:seed
```

### Проблема: "Permission denied"

```bash
# На Windows используйте:
npx prisma db seed

# На Mac/Linux используйте:
npm run prisma:seed
```
