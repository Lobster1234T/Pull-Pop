# AVATAR Platform - Seed Database Guide

## 📋 Описание

Seed скрипт инициализирует AVATAR Platform БД с основной конфигурацией:

- **7 базовых ролей** с полной системой разрешений
- **24 разрешения** для управления доступом
- **5 категорий меню** (напитки, еда, закуски, аксессуары, мерч)
- **Автоматическое связывание** ролей с разрешениями

## 🚀 Быстрый старт

### 1. Убедитесь, что БД создана

```bash
npm run prisma:migrate dev
```

### 2. Запустите seed скрипт

```bash
npm run prisma:seed
```

## 🔄 Повторный запуск

Скрипт **безопасен для повторного запуска**:
- Проверяет существование каждого объекта перед созданием
- Пропускает уже созданные элементы
- Не удаляет существующие данные

```bash
npm run prisma:seed
# Можно запускать сколько угодно раз
```

## 📊 Созданные роли

### 1. **Founder** (Основатель)
- **Доступ:** Полный (`*:*`)
- **Использование:** Основатель платформы
- **Права:** Контроль всей сети, управление филиалами, финансы, аналитика

### 2. **Director** (Директор)
- **Доступ:** Управление филиалом + аналитика
- **Права:** 
  - `branch.manage` - Полное управление филиалом
  - `booking.read` - Просмотр броней
  - `analytics.read` - Просмотр аналитики
  - `finance.read` - Просмотр финансов

### 3. **Manager** (Управляющий)
- **Доступ:** Операции в филиале
- **Права:**
  - Полное управление бронями
  - Управление заказами
  - Просмотр платежей
  - Управление местами
  - Финансовый учет

### 4. **Admin** (Администратор)
- **Доступ:** Управление содержимым
- **Права:**
  - Управление пользователями
  - Управление товарами и категориями
  - Создание и редактирование акций
  - Настройка системы

### 5. **Cashier** (Кассир)
- **Доступ:** Расчеты и платежи
- **Права:**
  - `booking.*` - Управление бронями
  - `order.*` - Управление заказами
  - `payment.*` - Полное управление платежами
  - Просмотр информации о местах

### 6. **Staff** (Персонал)
- **Доступ:** Ограниченный операционный доступ
- **Права:**
  - `booking.read` - Просмотр броней
  - `station.read` - Просмотр мест
  - `station.update` - Обновление статуса мест
  - `order.read` - Просмотр заказов

### 7. **Customer** (Клиент)
- **Доступ:** Для обычных пользователей
- **Права:**
  - Просмотр своих броней
  - Просмотр своих заказов

## 🔐 Система разрешений

Все разрешения следуют единой структуре: `module.action`

### Основные модули:

- **booking** - Управление бронями
  - `booking.read`, `booking.create`, `booking.edit`, `booking.cancel`

- **order** - Управление заказами
  - `order.read`, `order.create`, `order.accept`, `order.prepare`, `order.deliver`, `order.complete`, `order.cancel`

- **payment** - Управление платежами
  - `payment.read`, `payment.create`, `payment.process`, `payment.refund`

- **station** - Управление игровыми местами
  - `station.read`, `station.update`, `station.maintenance`

- **branch** - Управление филиалами
  - `branch.read`, `branch.create`, `branch.edit`, `branch.manage`

- **finance** - Финансовые операции
  - `finance.read`, `finance.create`, `finance.edit`, `finance.approve`

- **analytics** - Аналитика
  - `analytics.read`

- **user** - Управление пользователями
  - `user.read`, `user.create`, `user.edit`

- **employee** - Управление сотрудниками
  - `employee.manage`

- **product** - Товары
  - `product.read`, `product.manage`

- **settings** - Системные настройки
  - `settings.read`, `settings.edit`

- **promotion** - Акции
  - `promotion.read`, `promotion.create`, `promotion.edit`

## 🔧 Модификация seed

### Добавить новую роль

1. Добавьте роль в массив `ROLES`
2. Добавьте разрешения в объект `ROLE_PERMISSIONS`
3. Запустите: `npm run prisma:seed`

Пример:

```typescript
const ROLES = [
  // ... существующие роли
  {
    name: 'Support',
    code: 'support',
    description: 'Служба поддержки',
    isSystem: true,
  },
];

const ROLE_PERMISSIONS = {
  // ... существующие роли
  support: [
    'support.read',
    'support.respond',
    'ticket.manage',
  ],
};
```

### Добавить новое разрешение

1. Добавьте разрешение в массив `PERMISSIONS`
2. Добавьте его в нужные роли в `ROLE_PERMISSIONS`
3. Запустите: `npm run prisma:seed`

Пример:

```typescript
const PERMISSIONS = [
  // ... существующие разрешения
  {
    code: 'support.read',
    name: 'Просмотр тикетов поддержки',
    module: 'support',
  },
];
```

### Добавить новую категорию

1. Добавьте категорию в массив `PRODUCT_CATEGORIES`
2. Запустите: `npm run prisma:seed`

Пример:

```typescript
const PRODUCT_CATEGORIES = [
  // ... существующие категории
  {
    name: 'Игры',
    slug: 'games',
    description: 'Виртуальные игры и расширения',
    sortOrder: 6,
  },
];
```

## ✅ Проверка результатов

### Просмотреть созданные роли

```bash
npx prisma studio
# Открыть http://localhost:5555
# Перейти на Role
```

### SQL запрос

```sql
SELECT r.name, r.code, COUNT(rp.id) as permissions_count
FROM roles r
LEFT JOIN role_permissions rp ON r.id = rp.role_id
GROUP BY r.id, r.name, r.code
ORDER BY r.name;
```

## ⚠️ Важно

1. **Не удаляйте системные роли** - помечены `isSystem: true`
2. **Разрешение `*:*`** - специальное, означает полный доступ
3. **Безопасный запуск** - скрипт проверяет существование перед созданием
4. **Зависимости** - роли создаются ДО разрешений

## 🐛 Устранение проблем

### Ошибка: "Роль не найдена"

```
❌ Роль "unknown_role" не найдена
```

**Решение:** Убедитесь, что роль добавлена в массив `ROLES`

### Ошибка: "Разрешение не найдено"

```
❌ Разрешение "unknown.permission" не найдено
```

**Решение:** Убедитесь, что разрешение добавлено в массив `PERMISSIONS`

### Скрипт не создает данные

```bash
# Проверьте подключение к БД
echo $DATABASE_URL

# Запустите миграции
npm run prisma:migrate dev

# Повторите seed
npm run prisma:seed
```

## 📝 Логирование

Скрипт выводит четкие логи каждого действия:

- ✅ **Создано** - новый объект успешно создан
- ⏭️ **Пропущено** - объект уже существует
- ❌ **Ошибка** - объект не найден или ошибка БД
