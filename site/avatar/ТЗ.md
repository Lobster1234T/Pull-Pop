# AVATAR Platform

## 1. Резюме проекта

**AVATAR Platform** — единая цифровая платформа для управления сетью компьютерных клубов AVATAR.

Платформа объединяет в одной информационной системе:

- публичный сайт;
- PWA-приложение клиента;
- систему онлайн-бронирования;
- оплату;
- QR-систему;
- CRM клиентов;
- магазин напитков и еды;
- доставку заказов к игровому месту;
- Telegram-бот;
- приложение/панель сотрудников;
- управление филиалами;
- управление игровыми местами;
- управление тарифами;
- управление приходами и расходами;
- финансовый учет;
- новости и акции;
- программу лояльности;
- аналитику;
- систему уведомлений;
- AI-инструменты автоматизации;
- централизованную административную панель.

### Главный принцип

> **Один клиент — один аккаунт.**

> **Один сотрудник — один аккаунт с необходимыми правами.**

> **Все филиалы — одна система.**

> **Все операции — один источник данных.**

# 2. Бизнес-ценность для основателя

Платформа создается не только для удобства клиентов.

Главная задача — дать основателю полный контроль над бизнесом без необходимости вручную собирать информацию из разных источников.

Сегодня информация может находиться отдельно:

- Брони → отдельная система;
- Касса → отдельная информация;
- Telegram → сообщения сотрудников;
- Расходы → таблицы;
- Клиенты → разные базы;
- Продажи → касса;
- Филиалы → отдельные данные;
- Реклама → соцсети;
- Отчеты → сотрудники.

AVATAR Platform превращает это в единую систему:

```text
                    AVATAR PLATFORM

           ↓               ↓               ↓

> **Один экран → вся сеть → текущая ситуация → ключевые показатели → возможность перейти в детали.**

Основатель должен видеть не только общие показатели сети, но и иметь возможность провалиться в конкретный филиал, зону, игровой компьютер, бронирование, сотрудника, заказ или финансовую операцию.

## Важное архитектурное требование

Все перечисленные данные должны управляться через **CMS / Admin Panel**.

Нельзя делать:

- хардкодить адрес филиала в коде;
- хардкодить количество компьютеров;
- хардкодить характеристики компьютеров;
- хардкодить номера телефонов;
- хардкодить режим работы;
- хардкодить название филиала;
- хардкодить район;
- хардкодить маркетинговые показатели;
- хранить изменяемые данные только во frontend-коде.

### Правильный подход

Все изменяемые данные должны храниться в базе данных и редактироваться через административную панель.

Например:

```text
Admin Panel
    ↓
Настройки филиала
    ↓
Название
Адрес
Район
Телефоны
Режим работы
Количество игровых мест
    ↓
Database
    ↓
API / Backend
    ↓
Website / PWA / Telegram Bot
```

### Пример

Если количество компьютеров изменилось:

```text
Было: 103 компьютера
Стало: 120 компьютеров
```

Администратор должен изменить значение в **Admin Panel**, после чего новая информация автоматически отображается на сайте и в приложении.

Не требуется изменять исходный код и заново разворачивать frontend.
